During correction: denying directory write sharing initially prevented normal child-file publication; allowing READ/WRITE sharing while denying DELETE corrected it. It now requires exact preservation of the visible entry's kind/name, then separately verifies `_DEFAULT` recovery after removal. These failures exposed assertions that depended on the reported defects; no product security checks were relaxed. Both failed native runs independently confirmed ordinary application data unchanged. Restore confirmation text now explains deduplication accurately.

The third native run (`.tools/foundation/2026-10-21T21-22-32.224Z`) returned **1** in the new unavailable-storage verifier after the existing development/recovery/production checks passed. No ordinary data was moved.

The final full native run (`.tools/foundation/2026-10-21T21-29-51.426Z`) returned **0**, with **147 checkpoints** and **zero captured console issues**. It verifies development launch/HMR, interrupted-launch recovery, six-page navigation, simulator Cancel/reconnect/read and missing-SIM/DNS preview, genuine pinned OpenWrt SSH inspection, generated-binary Library/backup/restore workflows, production restart, inaccessible relocated storage and reconnection.
