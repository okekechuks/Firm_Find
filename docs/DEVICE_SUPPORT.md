# Device support

Windows discovery enumerates present USB/serial records and network adapters, correlating Windows ancestry and adapter identity. Notifications and optional periodic scans refresh passive host inventory. Separately, a saved endpoint can receive an explicitly approved, bounded HTTP/HTTPS check; this proves reachability only. Phase 7 also permits approved pinned SSH identity inspection of a router already running OpenWrt with existing key access. Configuration/metadata reads require a qualified exact profile and separate approval. No physical USB/serial command, firmware extraction or device write is enabled.

Windows-reported instance IDs and hardware IDs appear in local Device Explorer details. Stable SHA-256 identifiers are used as local inventory database keys. Raw hardware IDs and network addresses do not appear in audit records. An inventory match does not verify a router model, chipset, installed firmware, flash access, or feature support.

Router/MiFi detection labels are categorical hints from USB/serial/network relationships. A gateway proves neither identity nor ownership. Host network adapters remain protected; a saved router selected through an active physical route gets a separate remote-target context. Profiles and authenticated evidence determine authority, rather than USB IDs, labels or HTTP success. The proprietary MG11 remains unqualified: its supplied software version is unverified and APN, Wi-Fi limit, DNS and USSD remain UNKNOWN. The sealed genuine OpenWrt QEMU inspection profile qualifies controlled software interoperability only; physical radio/modem qualification remains pending. Local Library file backups do not imply firmware acquisition from a device. Installation remains unavailable.

Later validation candidates from the guidelines: GL.iNet GL-MT3000, Huawei E8372, TP-Link Archer AX23. These are candidates only; model names alone never grant extraction, feature-write, backup, build, or installation capabilities. Record the exact hardware revision, chipset, firmware, control plane, recovery path, and evidence before assigning support.

Capabilities must independently report SUPPORTED, UNSUPPORTED, UNKNOWN, REQUIRES_AUTH, REQUIRES_TOOL or EXPERIMENTAL. UNKNOWN never means supported.
