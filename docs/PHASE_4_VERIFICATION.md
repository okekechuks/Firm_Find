### Vault, import and consistency

Storage is `vault\sha256\<first-two-digest-characters>\<64-lowercase-SHA-256>.bin`; staging is `vault\staging\<32-hex-job-id>.part`. Names and descriptions never control these paths. A native Windows file picker returns an opaque, single-use five-minute ticket. Rust retains a source read lease; JavaScript cannot submit arbitrary source/destination paths. A separate React confirmation is required before a durable job is created.

Sources are regular local files. Validation rejects traversal, UNC/device paths, alternate data streams, mapped network drives, symlinks/reparse points, directories, unsupported names and excessive sizes. Directory leases prevent replacement during I/O; Windows source sharing denies concurrent writers/deletion. Internal application/vault files cannot be reimported or used as manifest destinations. Actual Windows junction and exclusive-handle regressions pass. A mapped network share was not available for physical qualification; its drive-type rejection is source-reviewed and compiled.

The pipeline persists intent, creates a new stage, streams copy/hash in 1 MiB chunks, checks size/source metadata, flushes/synchronizes, independently hashes staging, persists the candidate digest, publishes with same-volume `hard_link` without replacement, independently hashes/size-checks the final blob under a read lease, then commits metadata/import/integrity/job/activity together. It removes only its own known staging file. A library entry appears only after that transaction succeeds.

SQLite and filesystem publication are not one atomic transaction. A failed commit or cancellation after publication may leave a **complete retained orphan**, never a claimed successful partial artifact. Its digest/recovery context remains available, and a later reimport verifies bytes before reuse. Unknown staging and orphan blobs are preserved for review; no general garbage collector was added. Required hard-link support fails explicitly on unsupported filesystems. Vault immutability is enforced by application operations, not a security boundary against the Windows file owner.

Same bytes/same filename and same bytes/different filenames deduplicate to one blob while recording distinct import occurrences. Same filename/different bytes yields separate artifacts. Queued concurrent identical imports, corrupt existing destinations, post-publication SQL failure and retry/reuse all have passing isolated tests. User imports always have `user_import` and `unverified` provenance. Extensions grant no format/support claim; format stays `UNKNOWN`.

### Jobs, integrity and frontend

One worker, a bounded channel and at most 16 active/queued operations limit resource use. At most eight selection tickets retain handles. Default maximum import size is 2 GiB, configurable from 1 byte to 8 GiB through `OBTAINER_IMPORT_MAX_BYTES`. Actual progress is saved and emitted approximately every 100 ms; React validates events and refetches persisted data, with a 1.5-second polling fallback. Hashing/copying never holds the SQLite mutex.

Pending jobs may become running/cancelled/failed; running jobs may complete/cancel/fail. Terminal jobs cannot restart. Cancellation is idempotent and checked between chunks/transitions. A finalization fence orders cancellation against commit. Startup converts unfinished owned jobs to failed/`INTERRUPTED`, removes only their regular known staging files and reconciles artifact availability/size in pages of 128. Graceful shutdown stops admissions, requests cancellation and waits at most two seconds; forced termination relies on durable recovery.

Explicit integrity jobs stream stored bytes and compare both SHA-256 and size. Missing, unreadable, mismatched and general verification-failure results are distinct and persisted. A cancelled duplicate check does not poison a valid artifact. Startup withdraws a prior `verified` label to `not_checked` rather than claiming old verification is current. Corruption/deletion tests operate only on temporary test vaults; the real saved artifact was not corrupted.

Library supports backend search by filename/hash, source/integrity/UTC-date filters and 25-row pages. Details show the latest 50 import/check records; SQLite retains full history. Jobs/activity show the latest 100 records. Loading, empty, confirmation, progress, duplicate success, export, error, interruption, stale-response rejection and browser-without-IPC states have frontend coverage. Existing nine destinations remain functional. Dashboard uses real snapshot counts and refreshes on terminal job changes.

Manifest schema 1 is a bounded unsigned JSON metadata export via a real Windows Save dialog. It includes digest/size/format/current integrity and latest 50 source records plus total/omission counts. Absolute source paths, descriptions, device IDs and credentials are excluded. The backend creates and synchronizes a temporary file, publishes without overwriting, and records activity. Export is bounded off-UI metadata work rather than a queued binary job. Checksums establish byte equality, never authenticity, compatibility or flashing support.
