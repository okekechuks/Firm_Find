## Security corrections and regressions

Independent source review identified and corrected the following before acceptance:

1. Established reads could outlive the time captured in the context. Controls now use the earliest caller/binding/grant/evidence deadline, checkpoint each bounded query and reauthorize with fresh time before publishing.
2. The OpenWrt service's private session manager missed discovery invalidation. Discovery now cancels the current service scope, prevents further queries and rejects old publication; current target/evidence is resolved again before authentication after modal key selection.
3. Host-target exclusion checked only the selected NIC. Selection now rejects any address belonging to the PC across all observed NICs, as well as invalid/loopback/multicast targets outside the sealed test-only lab. Scoped link-local IPv6 is rejected because this transport lacks an explicit zone binding.
4. Failed authentication/read could retain consumed observations or dead-session authority. Owner-scoped failure cleanup clears the session, grant and cached report without clearing another operation's ownership.
5. Native key selection previously preceded busy admission. One RAII operation now owns selection, authentication and publication; the picker has cancellation and a bounded Windows timer. Competing calls reject before opening another dialog.
6. Lab profile origin handling and sorted lookup initially prevented an authoritative exact match. The native-only constructor now validates its sealed profile, retains authority inside its owned scope and sorts lookup entries. Imported/local previews remain untrusted.

Deterministic unit tests cover closed query schemas/limits, untrusted profiles, unknown hardware fields, exact OS identity, endpoint/source/evidence substitution, all-host-address exclusion, busy ownership, cancellation, stale publication, discovery invalidation, expiry, picker admission and denied IPC injection. A loopback TCP sink tests SSH cancellation/timeout cleanup after an accepted connection; it is explicitly not evidence of SSH protocol compatibility. All earlier adapter, simulator, storage and firmware regressions remain in the full suites.

### Initial failures and corrections

- Windows optional-feature OpenSSH 9.5 keyscan could not negotiate the guest's key exchange. Qualified existing Git OpenSSH 10.2 was selected explicitly; no algorithm downgrade or host-key bypass was added.
- The first guest setup ran before `br-lan` existed. A bounded interface readiness check fixed setup; original and retry console logs remain.
- Nested double quotes in the Windows `UserKnownHostsFile` argument reached OpenSSH as invalid configuration. Forward slashes and a single-quoted option value fixed it, including a diagnostic path containing spaces; strict known-host checking remained enabled.
- Two genuine tests failed after their background WSL VM exited. The owned foreground `serve` command now retains QEMU for the duration of verification and records/validates ownership before shutdown. Genuine tests then passed.
- Existing adapter fixture assertions expected a declared placeholder; they now expect the same contract as a built-in read-only adapter and retain all deny/write assertions.
- A lab profile initially had an invalid evidence URL and later lacked authoritative origin/sorted lookup. Strict validation exposed these problems; exact sealed lab construction was corrected rather than weakening the production validator.
- The new TCP-sink regression initially expected `OPERATION_TIMEOUT`; this connection-stage timeout correctly yields `CONNECTION_TIMEOUT`. Only that test expectation and guaranteed sink cleanup were corrected. The initial full run had 191 passes/1 failure; the next run passed all 192.
- Initial formatting failed on new source; `fmt --all` corrected it. Clippy rejected a test module before production items; moving the module to the file end resolved the warning without functional changes.
- Final tooling review on 21 October reproduced `Unsupported contract kind: ZodEffects` in the schema generator. It now unwraps only the known refinement, generates separate versioned schemas, and exports the inspection-only UNKNOWN restrictions. Existing schema 1 remains byte-identical (`A025695108C0EABAF8EAEC4FE187D698FAE63A7F93FE5B758BF7B24E500BFE63`). Generation, explicit output assertions and lint passed. This follow-up changed export tooling/documentation only; the tested application source and executables were unchanged.
