# Application security model

The current command surface is explicitly enumerated in `apps/desktop/src-tauri/build.rs` and registered in `src/lib.rs`. Permissions live in `capabilities/main.json` and isolated-only `capabilities/simulator.json`. It includes workspace/settings, passive Windows discovery, user-approved bounded HTTP/HTTPS endpoint checks, profile/evidence evaluation, picked-file Library jobs/backups, storage recovery, the isolated stateful simulator, and explicitly approved pinned SSH OpenWrt identity/inspection. It exposes no arbitrary shell command, SQL, general network request or caller-supplied raw file path. Firmware extraction, configuration writes to physical devices, flashing and live USSD remain disabled.

Settings use a closed theme enum and reject unknown JSON fields. SQL values are bound parameters. Snapshot and settings responses are checked at the frontend boundary. Backend errors return an actionable code and message; internal database errors stay in local structured logs.

Application ACL permissions are generated from an explicit command manifest and granted only to the local main window. Production CSP loads local assets and permits only Tauri IPC connections. The development CSP additionally permits the fixed localhost Vite server. Remote application code is not loaded.

Database, logs and backups use Windows LocalAppData under `OBTAINER`. The Library can be explicitly relocated through native selection and verified copy. An unavailable relocated root is not silently recreated or replaced; metadata/settings remain accessible. Confirmed recovery can select default storage for the next restart, retaining inaccessible originals and existing records. Directory leases reject reparse paths and deny deletion/rename while held. A per-user workspace instance mutex is acquired before opening storage. Fatal production startup failures have a native dialog. Local database/log storage is not encrypted. SSH private-key content is never sent to the frontend or persisted by OBTAINER; the native-selected key reference is passed to the qualified OpenSSH process, with agent/password/helper authentication disabled.

The adapter framework separately authorizes a single-use initial handshake and established reads. Endpoint/interface/source/pin/evidence/expiry are bound in backend-owned receipts. Protected PC hardware, ambiguous/conflicting identity and stale sessions remain denied. OpenWrt fingerprint review lasts up to ten minutes; key selection is bounded to two minutes, authentication to thirty seconds, and successful authentication starts a fresh five-minute read lease bounded by evidence freshness. Each configuration inspection requires separate single-use approval and one bounded SSH call containing only fixed, independently framed queries with before/after board identity checks. Optional metadata failures remain explicit UNKNOWN limitations; identity/trust/cancellation/timeout errors propagate. The observed fingerprint is hidden during independent entry; the UI cannot prove the user consulted an independent source. Physical hardware qualification remains pending.

The simulator permits modeled changes only with backend-private virtual provenance; physical adapters cannot be selected through simulation IPC. Future physical configuration writes require preview, explicit consent, verified before-state, independent verification and rollback/recovery. Installation must be profile-specific, integrity checked and recovery tested; no generic flashing command exists.

WSL2 is not a complete sandbox for hostile binaries. Future parsing/extraction must use bounded isolated workers and copies of originals. Signing, updater verification, parser fuzzing, and hardware acquisition are not implemented in this foundation.
